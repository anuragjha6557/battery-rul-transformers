# Contributing

Thanks for looking. This is a research benchmark, so the rules protect correctness first.

## Setup
Python 3.12 with [uv](https://docs.astral.sh/uv/). Do not use a system Python 3.13+.
```bash
make env     # uv sync --all-extras, installs pre-commit hooks
make data    # optional: download (checksummed) + build parquet; needs data/raw
```
Unit tests use synthetic data, so `make env` is enough to run them. Real-data tests carry `@pytest.mark.data` and are skipped by default (`make test-all` runs them).

## Checks before every commit
```bash
set -o pipefail; make lint test typecheck
```
- `make lint`: ruff lint and `ruff format --check`. `make format` fixes both.
- `make test`: the main pytest run, then `tests/lgbm` in a second process (see below).
- `make typecheck`: mypy on `src/`.
- Always check the exit code. Piping a gate through `grep` once hid a failure.

## The OpenMP isolation rule (macOS)
torch and LightGBM load different `libomp` copies that cannot share a process, in either import order.
- Never import `lightgbm` or `torch` at module top level outside their model modules.
- Model classes load lazily through `models/registry.py`, which records each model's OpenMP family. The runner puts mixed experiments in per-unit worker processes.
- LightGBM tests live in `tests/lgbm/` and run in a separate pytest process. Linux CI is unaffected, so green CI does not prove macOS works. Run `make test` locally.
- Serving code must be CPU-only: use `battery_rul.utils.resolve_device("auto")`, never MPS-specific code.

## Adding a model
1. Implement the `Model` protocol from `src/battery_rul/models/base.py`:
   - class attributes `name`, `supported_tasks`, `probabilistic`;
   - `fit(train, val=None) -> FitInfo` and `predict(samples) -> Prediction`.
   - It receives a `SampleSet` that already obeys the leakage rules. It must not read `samples.y` in `predict`, and `cycle_idx` and `cell_id` are never inputs.
2. Register it in `_PATHS` in `src/battery_rul/models/registry.py` as `"module:Class"` with its OpenMP family (`"torch"`, `"lightgbm"` or `None`). Optional class traits: `cross_fit` and `tunable` (default true).
3. Add `configs/model/<name>.yaml` with the search space. Tunable models need a tuning run (`battery-rul tune`) and then a `configs/tuned/<name>__<task>.yaml`. Equal budget for every model: 50 trials ([ADR-0006](docs/decisions/0006-equal-budget-tuning.md)).
4. Add unit tests with synthetic data. Declare units in docstrings (Ah, %SOH, cycles).
5. If the model changes features, splits or tasks, `tests/test_leakage.py` must stay green.

## Adding an experiment config
Every experiment is a Hydra config under `configs/experiment/`, and every reported number maps to an MLflow run ID.
1. Copy a similar file (for example `benchmark.yaml`, or `field_final_nasa.yaml` for the field setting). Set `name`, `datasets`, `tasks` and `models` (use `tuned:` references for tuned models).
2. Run `battery-rul benchmark --config <name>`. Runs are resumable.
3. Tables come from `battery-rul report`. Results tables in the README are generated by `scripts/make_readme_tables.py` and are never hand-edited.
4. Do not merge into `main` while a sweep or benchmark is running.

## ADR process
Every non-trivial choice gets a one-page ADR in `docs/decisions/NNNN-title.md`: Context, Options considered, Decision, Evidence, Consequences ([ADR-0001](docs/decisions/0001-record-architecture-decisions.md)).
- An experiment's ADR is written and committed **before** the run, with a pre-registered hypothesis and decision rule. The outcome is appended afterwards.
- Cite MLflow run IDs or the table that supports it.
- Superseded ADRs are marked, not deleted. Add the new one to `docs/decisions/README.md`.
- Honest negative results are expected and reported.

## No data or weights in git
Never commit raw data, parquet, `mlruns/`, `mlflow.db`, model weights, ONNX files or notebooks with outputs. Weights live on the Hugging Face model repo; the Space downloads them. Scratch files go outside the repo.

## Commits
Conventional messages (`feat(data): ...`, `test(eval): ...`, `docs(adr): ...`), one branch per piece of work, squash-merged to `main`.
