1Point prediction

A model predicts one number, for example: "In 50 cycles this battery's SOH will be 85.0 %." The real value will almost never be exactly 85.0. It might be 84.2 or 86.1, and a single number says nothing about how wrong it could be.

2Prediction interval

A better answer is a range plus a confidence level: "SOH will be between 83.5 % and 86.5 %, and I am 90 % confident the truth lands inside." That is a 90 % prediction interval.

Blue bar = 90 % interval [83.5, 86.5]; black tick = point prediction 85.0.

The "90 %" is a promise: across many such predictions, about 9 in 10 true values should fall inside their intervals. For battery decisions the width matters. "85 ± 1.5" and "85 ± 10" lead to very different maintenance choices.

3Is the interval honest? Coverage

Test the promise on predictions where the truth is known. The fraction of truths that land inside is the coverage, called PICP (prediction-interval coverage probability):

$$\text{PICP} = \frac{1}{N}\sum_{i=1}^{N} \mathbf{1}\big[\,\ell_i \le y_i \le u_i\,\big]$$

\(\ell_i, u_i\) are the lower and upper ends of interval \(i\), \(y_i\) is the true value, and \(\mathbf 1[\cdot]\) is 1 if true and 0 if false.

Over-confident (too narrow)The truth lands inside 74 of 100 times: it promised 90 % and delivered 74 %. This really happened with raw LightGBM on CALCE.
Under-confident (too wide)The truth lands inside 99 of 100 times. It is honest but wasteful; the intervals could be tighter.
Well calibratedThe truth lands inside about 90 of 100 times. The promise matches reality.

Calibration means making measured coverage match the promised level, with intervals that are as narrow as possible.

4Approach A: Gaussian intervals (mean ± k·σ)

This is the classic approach, and the one you might expect. The model predicts a mean \(\mu(x)\) and a standard deviation \(\sigma(x)\), and assumes the error is normally distributed:

$$\big[\,\mu(x) - z\,\sigma(x),\;\; \mu(x) + z\,\sigma(x)\,\big], \qquad z = z_{0.95} = 1.645 \text{ for a 90 % interval}$$
Example\(\mu = 85.0,\ \sigma = 0.9\) gives \(85.0 \pm 1.645\times 0.9 = [83.5,\ 86.5]\).

In this project only the Gaussian-process (GPR) baseline works this way. Its weakness is that the interval is always symmetric and only as good as the normality assumption. Battery errors are often skewed: regeneration bumps push SOH up, while artifacts and late-life knee points push it down. In our pilot, GPR's "90 %" intervals covered only 54 % at a 50-cycle horizon.

5Approach B: quantile regression (no distribution assumed)

Our main models (LightGBM and all neural networks) skip the mean, the σ and the density. They directly predict quantiles \(\hat q_\tau(x)\): values the truth should fall below with probability \(\tau\).

Level \(\tau\)MeaningExample
0.05only 5 % chance the truth is lower82.9
0.50the median, used as the point prediction85.0
0.95only 5 % chance the truth is higher85.8

The 90 % interval is simply \([\hat q_{0.05}(x),\ \hat q_{0.95}(x)]\), here [82.9, 85.8]. It is lopsided: 2.1 below the median and 0.8 above, because the model learned that downside surprises are bigger. Mean ± kσ cannot express that.

The model learns quantiles by minimising the pinball (quantile) loss:

$$L_\tau(y,\hat q) = \max\!\big(\,\tau\,(y-\hat q),\;\; (\tau-1)\,(y-\hat q)\,\big)$$

For \(\tau = 0.95\), predicting too low (\(y > \hat q\)) costs \(0.95\times\) the gap, while predicting too high costs only \(0.05\times\) the gap. The loss is smallest when the truth falls below \(\hat q\) exactly 95 % of the time. So the model learns the real 95th percentile, whatever the shape of the distribution. The neural models output all five levels {0.05, 0.25, 0.5, 0.75, 0.95} at once; LightGBM fits one model per level. If the predicted levels ever cross, they are sorted (quantile rearrangement).

6Approach C: conformal calibration (CQR)

Quantile models can still be over- or under-confident. Conformalised Quantile Regression (Romano et al., 2019) measures the miss on data the model never trained on and shifts the intervals to fix it.

Step 1. Score each calibration point. The calibration data are the predictions on the inner held-out cells from cross-fitting, never the test cell. For each of the \(n\) points, compute how far the truth fell outside the interval (negative if it was inside):

$$E_i = \max\!\big(\,\hat q_{0.05}(x_i) - y_i,\;\; y_i - \hat q_{0.95}(x_i)\,\big), \qquad i = 1,\dots,n$$

Step 2. Take a finite-sample quantile of the scores, with \(\alpha = 0.10\) for 90 %:

$$c = \text{the } k\text{-th smallest } E_i, \qquad k = \big\lceil (n+1)(1-\alpha) \big\rceil$$

Step 3. Widen (or narrow) every new interval by \(c\):

$$C(x) = \big[\,\hat q_{0.05}(x) - c,\;\; \hat q_{0.95}(x) + c\,\big]$$

Guarantee: if calibration and test points are exchangeable (statistically interchangeable), then

$$\Pr\big(\,y \in C(x)\,\big) \;\ge\; 1-\alpha = 90\%$$

This needs no distribution assumption at all.

Worked example\(n = 999\) calibration points give \(k = \lceil 1000 \times 0.9 \rceil = 900\), so \(c\) is the 900th smallest score.
If \(c = +0.7\): [82.9, 85.8] becomes [82.2, 86.5] (too narrow, so it widens).
If \(c = -0.3\): it becomes [83.2, 85.5] (too wide, so it narrows).
The point prediction (85.0) never changes, and the skew is kept because both ends move by the same \(c\).
Blue = raw quantile interval (misses the orange truth); green = CQR-calibrated interval, wider by \(c\) on both ends.

Point-only models (persistence, ElasticNet) have no quantiles, so they use absolute residuals:

$$E_i = |\,y_i - \hat y_i\,|, \qquad C(x) = \big[\,\hat y(x) - c,\;\; \hat y(x) + c\,\big]$$

Rule 7 of PROTOCOL.md is enforced in code: calibration refuses to run if any test cell appears in the calibration data.

7Approach D: deep ensemble (ablation arm)

Train the same model with 5 random seeds and average each quantile level across members:

$$\hat q_\tau^{\,\text{ens}}(x) = \frac{1}{5}\sum_{s=1}^{5} \hat q_\tau^{(s)}(x)$$

This captures uncertainty from training randomness. CQR can be applied on top. ADR-0011 compares raw, CQR, ensemble and GPR.

10The caveat

The conformal guarantee assumes exchangeability. Here it holds only approximately: consecutive cycles of one battery are strongly correlated, and the test battery is a different battery from the calibration ones. The effective calibration sample is closer to "about 3 cells" than "999 points". That is why coverage is measured on the held-out test cells and reported rather than assumed from the formula (PROTOCOL.md §3, §5).
